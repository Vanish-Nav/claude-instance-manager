# Architecture and storage

- The product is Electron-only. The legacy Windows project is not part of the supported application path.
- Main-process modules: `windows-claude-install.ts` (install resolver), `windows-profile-paths.ts` (primary profile location), `windows-profile-backup.ts` (backup tiers, project transcripts, sizes), `windows-adapter.ts` (orchestration, processes, Sign In, router). Pure logic lives in the first three so it can be tested without Electron (`tests/*.test.cjs`, loaded through `tests/load-source.cjs` with `electron` and `node:child_process` replaced; adapters are constructed under the fixture environment and must never see the real user folders).
- The primary Claude profile is shown as **Claude** with the `PRIMARY` badge. Detect the MSIX container at `%LOCALAPPDATA%\Packages\<Claude package family>\LocalCache\Roaming\Claude`, migrated data at `%LOCALAPPDATA%\Claude-Data\<package family>`, and legacy `%APPDATA%\Claude` / `%APPDATA%\Claude Code`. A `Claude-Data` root with profile files is also supported. Respect Claude's `.user-data-left.<family>` / `.user-data-back.<family>` migration markers; empty container roots are not profiles. If both legacy roaming folders exist, prefer `Claude`.
- The package family comes from the install resolver (see runtime.md). Do not hardcode the publisher suffix in profile paths. The live primary's single-instance window title is the authoritative data folder when it is available (`settings.json: lastPrimaryDataPath`).
- Isolated profiles are stored at `%LOCALAPPDATA%\ClaudeInstanceManager\Profiles\CIM-Profile-<GUID>`.
- A profile folder name is immutable. Display name and color are stored in `instance.json` in the profile root so renaming does not break paths or shortcuts.
- Instance names accept up to 20 English letters, digits, and spaces. Name collisions are resolved or rejected by the profile-management flow.
- Manager files: `settings.json` (`deepLinkRouter`, `portableCleanupDismissed`, `lastPrimaryDataPath`, `lastFocusedProfileId`), `sign-in-state.json` (active relay), `sso-state.json` (legacy recovery only).

## Backups, exports, archives

- Backups are under `%LOCALAPPDATA%\ClaudeInstanceManager\Backups\<profile-id>\<timestamp>` (a `-2`, `-3` suffix when two items fall into one second); archives under `Archives\<profile-id>\<timestamp>`. `.cim-storage.json` in the item carries `profileId`, `profileName`, `kind` (`backup` | `archive`), `tier`, `createdAt`, `sizeBytes`. Items without a `tier` were complete copies and import as `full`.
- Tiers (`windows-profile-backup.ts`):
  - `session`: `config.json`, `Local State`, `Network`, `Local Storage`, `IndexedDB`, `Session Storage`, `Preferences`, `ant-did`, `claude_desktop_config.json`, `mcp-user-tool-toggles.json`, `claude-code-sessions`, `local-agent-mode-sessions`, `spaces-present`, `Claude Extensions`, plus `.cim-claude-projects\<slug>` copies of `%USERPROFILE%\.claude\projects\<slug>` for every `cwd` found in `claude-code-sessions\<space>\<account>\local_*.json` (slug = path with `:` and `\` replaced by `-`).
  - `full`: everything except `Cache`, `Code Cache`, `GPUCache`, `GrShaderCache`, `DawnGraphiteCache`, `DawnWebGPUCache`, `ShaderCache`, `vm_bundles`, `claude-code`, `claude-code-vm`, `logs`, plus the project transcripts.
  - `settings`: the session tier without `Network`, `Local State`, `ant-did`, and with the `oauth:*` keys removed from `config.json`. Meant for another machine; the login is DPAPI-bound to the Windows user and cannot travel.
- Restore: `full` replaces the folder; `session` replaces only session entries and keeps caches; `settings` keeps the target's `Network`, `Local State`, `ant-did` and merges its `oauth:*` keys back into `config.json`. Transcripts are copied back without overwriting newer local files. The result lists Code sessions whose `cwd` does not exist on this machine.
- Copy from another instance (`cloneSession`): `restoreTier(source, target, tier)` between two profiles on this machine (the primary may be the source). Tier `settings` leaves the target's login and device id alone and is the way to split one primary with several accounts into instances (export/copy settings, then Sign In per instance). Tier `session` also copies the login and gives the target a new `ant-did`; the copy shares one refresh token with the source, so a sign-out or a token rotation there can end it. Transcripts are shared through `%USERPROFILE%\.claude` and are not copied.
- Import and copy accept an `ImportSelection`: the Code projects (working directories) whose sidebar entries are restored, and whether `local-agent-mode-sessions` (Cowork) comes along. `sourceContents` lists what a backup, export or live profile holds (projects with session counts and whether the folder exists here). Unselected projects lose their `local_*.json` entries in the target and their transcripts are not restored; `projects: null` means no filter.
- Clean caches deletes selected cache entries of a stopped instance; sizes come from `profileSizes`, one walk per request.
- Backups and archives contain complete Claude profile data, including potentially active sign-in sessions. Treat them as sensitive. Settings exports do not.
- `process.noAsar = true` is set at the top of the main process: Electron's Node `fs` otherwise presents every foreign `app.asar` (the old portable copy, possibly an extension) as a directory, opens the archive on the first walk and keeps the handle, which makes the file undeletable by anyone. Keep it; the main bundle is one file and needs no asar support.
- Installer uninstall must never delete `%LOCALAPPDATA%\ClaudeInstanceManager` or its profiles, backups, and archives.
